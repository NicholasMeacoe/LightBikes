# LightBikes Project Structure

## File Organization

### Core Game Files
```
├── index.html          # Entry point with Three.js CDN and UI
├── script.js           # Main orchestrator - coordinates all components
├── game.js             # Game state management and entity updates
├── ai.js               # AI decision-making and pathfinding
├── collision.js        # Collision detection engine
├── controls.js         # Player input handling
├── renderer.js         # 3D rendering with Three.js
└── bundle.js           # Built output (generated by browserify)
```

### Test Files
```
├── game.test.js        # Game logic tests
├── ai.test.js          # AI behavior tests
├── collision.test.js   # Collision detection tests
└── coverage/           # Test coverage reports
```

### Documentation
```
├── DESIGN.md           # Technical architecture documentation
├── GAME_LOGIC.md       # Game mechanics and rules
├── ROADMAP.md          # Feature development roadmap
└── .kiro/steering/     # AI assistant guidance files
```

### Configuration
```
├── package.json        # Dependencies and build scripts
├── package-lock.json   # Dependency lock file
└── .env               # Environment variables (if any)
```

## Module Dependencies

### Import/Export Pattern
All modules use CommonJS exports:
```javascript
// Export pattern
module.exports = { ClassName };

// Import pattern  
const { ClassName } = require('./filename.js');
```

### Dependency Graph
```
script.js (orchestrator)
├── game.js (no dependencies)
├── ai.js (no dependencies) 
├── collision.js (no dependencies)
├── controls.js → game.js
└── renderer.js → THREE.js (external CDN)
```

## Component Responsibilities

### script.js - Main Orchestrator
- Initialize all components
- Coordinate game loop (animate function)
- Handle UI events (restart, touch controls)
- Manage component lifecycle

### game.js - Game State
- Core game state management
- Entity position tracking (player, AI)
- Trail management
- Direction changes and movement
- Game restart logic

### ai.js - AI Controller  
- AI decision-making algorithms
- Whisker-based obstacle detection
- Defensive pathfinding strategy
- State management (defensive/random modes)

### collision.js - Collision Detection
- Boundary collision detection
- Trail collision detection (self and opponent)
- Grace period handling (first 10 frames)
- Collision tolerance (0.1 units)

### controls.js - Input Handling
- Keyboard event listeners
- Direction change validation (no 180° turns)
- Touch control integration

### renderer.js - 3D Rendering
- Three.js scene management
- Camera positioning and following
- Trail segment rendering
- Lighting and materials
- Arena visualization (grid, boundaries)

## Naming Conventions

### Files
- Lowercase with hyphens for multi-word files
- `.test.js` suffix for test files
- `.js` extension for all JavaScript files

### Classes
- PascalCase (e.g., `Game`, `AIController`, `RenderingEngine`)
- Descriptive names indicating responsibility

### Methods
- camelCase (e.g., `getGameState`, `calculateAIDirection`)
- Verb-noun pattern for actions
- Boolean methods start with `is` or `has`

### Variables
- camelCase for local variables
- Descriptive names (avoid abbreviations)
- Constants in UPPER_CASE

## Data Flow Architecture

### State Management
- `Game` class is single source of truth
- Components receive read-only state via `getGameState()`
- No direct state mutation by external components
- Immutable state snapshots for consistency

### Update Cycle
```
Input → AI Decision → Game Update → Collision Check → Render → Repeat
```

### Component Communication
- Orchestrator (`script.js`) coordinates all interactions
- No direct component-to-component communication
- Data flows through well-defined interfaces
- Event-driven for user input

## Extension Points

### Adding New Components
1. Create new `.js` file with CommonJS export
2. Add corresponding `.test.js` file
3. Import in `script.js` and integrate in game loop
4. Update this documentation

### Adding New Game Modes
- Extend `Game` class or create mode-specific classes
- Add mode selection UI in `index.html`
- Update orchestrator to handle mode switching

### Adding New AI Strategies
- Extend `AIController` or create new AI classes
- Implement same interface (`calculateAIDirection`)
- Add strategy selection mechanism
